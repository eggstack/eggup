# Verified Update Core Milestone 012 — 0.1.x public-error compatibility corrective

Status: closed; implemented in `cb9d045`, hosted-green in `37527706900`. `Error` keeps the seven published 0.1.2 variants; retained evidence moved to `RecoveryError`

Repository baseline: `44d7fdf6d31d67a2e2c8b0f62aa4f00ec365daeb`

Source roadmap: `plans/subsystems/verified-update-core-roadmap.md`

Primary class: API compatibility / release corrective

Hard dependencies:

- Verified Update Core M010 and M011 are closed with hosted Stable/MSRV/macOS/Windows run `37376971555`.
- `eggup-core 0.1.2` is the current published baseline.
- The M010/M011 APIs have not been published, so their new method signatures may still be corrected without downstream migration.

## 1. Objective

Make the hosted-qualified M010/M011 substrate publishable as a Cargo-compatible `eggup-core 0.1.3` without silently breaking existing `^0.1.0` consumers.

The published `0.1.2` public `Error` enum has exactly seven variants:

- `InvalidInput`
- `UnknownMember`
- `Io`
- `UpdateInProgress`
- `DestinationConflict`
- `VerificationFailed`
- `CandidateExecution`

The current unpublished tree adds `Error::Injected` and `Error::RecoveryRequired`. Because `Error` is not `#[non_exhaustive]`, either addition breaks a downstream exhaustive match even though Cargo treats `0.1.2 -> 0.1.3` as compatible.

M012 restores the published Error surface while retaining all M010/M011 safety semantics.

## 2. Decision

Prefer a compatibility-preserving `0.1.3` over an unnecessary `0.2.0`.

Required shape:

1. **Fault injection is not a production public error variant.**
   `Error::Injected` must disappear from the normal packaged public API.
   Structural injected-failure classification remains internal/test-only and must not regress to substring matching.

2. **Recovery-required lock failures use a new recovery-specific additive error type.**
   Introduce a new public type, conceptually:
   ```rust
   #[non_exhaustive]
   pub enum RecoveryError {
       Core(Error),
       RecoveryRequired { evidence: PathBuf, detail: String },
   }
   ```
   Exact naming is implementation-owned. It must expose the real retained evidence path and support `From<Error>` or equivalent ergonomic propagation.

3. **Only the new M011 opt-in APIs use the recovery-specific result.**
   Existing published APIs keep `eggup_core::Result<T> = Result<T, Error>` unchanged.
   `MutationLock::acquire_with_recovery`,
   `ValidatedTransaction::commit_with_stale_lock_recovery`, and
   `commit_with_post_commit_and_stale_lock_recovery` may change signatures because they are still unpublished.

4. **Transaction receipts keep their existing recovery semantics.**
   `TransactionDisposition::RecoveryRequired`, `CleanupDisposition::RetainedForRecovery`, and `FailureCategory::RetainedEvidence` remain the structured terminal transaction surface. Do not collapse retained evidence into generic text.

Do not add `#[non_exhaustive]` to the already-published `Error` enum in this patch: that change itself breaks existing exhaustive matches. Future Error extensibility belongs to an intentional 0.2/1.0 boundary.

## 3. Invariants

- All M010 current-executable replacement/rollback behavior remains unchanged.
- All M011 exact-record stale-lock claim/race behavior remains unchanged.
- Retained recovery evidence always carries a real filesystem path.
- Default `MutationLock::acquire` remains fail-closed.
- No message-substring parsing determines injected versus production failure categories.
- Existing public 0.1.2 methods keep signatures and result types.
- Existing public `Error` variant set remains source-compatible with 0.1.2.
- New recovery-specific enums are `#[non_exhaustive]` from first publication.
- Core remains transport/service/release-policy independent.
- Rust 1.89 and no first-party unsafe remain intact.

## 4. Required production changes

### 4.1 Remove Error::Injected from the packaged API

Refactor the test fault harness so injected failures are represented structurally without a normal-build public `Error` variant.

Acceptable approaches include:

- a test-only/private fault marker converted directly to `FailureReport { category: Injected }`;
- `#[cfg(test)]`-only representation where the packaged public enum remains byte/API-equivalent to 0.1.2;
- a private internal failure enum used only by the fault harness.

Do not return to the former behavior of detecting injected failures by matching the string `"injected"`.

The lock-creation injected-failure test may assert a generic public error plus separate structural harness evidence; no production caller needs an Injected public variant.

### 4.2 Introduce RecoveryError for stale-recovery APIs

Move the current `Error::RecoveryRequired { evidence, detail }` state into a new recovery-specific error type.

Required properties:

- `#[non_exhaustive]`;
- retained `PathBuf` evidence is accessible programmatically;
- bounded human-readable detail;
- ordinary Core errors remain distinguishable and chain/source correctly;
- the caller can match a recovery-required case without parsing Display text.

### 4.3 Retype only unpublished recovery entry points

Change only the M011-added public entry points to return the recovery-specific result.

Existing published APIs including `MutationLock::acquire`, preparation, verification, validation, `commit`, and `commit_with_post_commit` remain unchanged.

Internal orchestration may use a private common error/result type if needed, but no published signature may drift.

### 4.4 Preserve receipt-level RecoveryRequired

Transaction rollback uncertainty remains represented by the already-existing `TransactionReceipt` disposition and recovery path. The new `RecoveryError` is for failures that cannot truthfully produce a transaction receipt, especially stale-lock claim/recovery before the live artifact transaction owns the domain.

Do not create two competing meanings for the same event.

## 5. Compatibility proof

Create a small external compatibility fixture outside the workspace.

Fixture A — published exhaustive match:

- first compile against `eggup-core = "=0.1.2"`;
- exhaustively match all seven published `Error` variants with no wildcard;
- retarget only the dependency source to the candidate package;
- it must still compile unchanged.

Fixture B — published service transitive compatibility:

- depend on `eggup-service = "=0.1.2"`;
- patch only `eggup-core` to the candidate package/path;
- compile and run representative M006 disposition/lifecycle type usage;
- prove the caret dependency does not become source-incompatible.

Fixture C — M011 recovery API:

- prove `ProvenStale` success;
- prove `Active`/unknown contention;
- prove retained-evidence failure is matchable through the new recovery type and names a real path.

The package-facing API diff must show no added variant on the old `Error` enum.

M012 closes only when:

- the packaged public `Error` enum has the same variant set as 0.1.2;
- no old public method signature changed;
- injected-failure classification remains structural and non-public;
- recovery-required stale-lock failures remain typed and retain real evidence;
- only unpublished M011 APIs changed signatures;
- the unchanged exhaustive-match fixture compiles against both 0.1.2 and the candidate;
- `eggup-service 0.1.2` compiles/runs with the candidate Core;
- M010/M011 behavioral suites remain green;
- full hosted matrix is green.

## 10. Stop conditions

Stop and open an explicit 0.2.0 API-boundary plan if preserving the 0.1.2 Error surface would require weakening M010/M011 safety semantics, hiding retained evidence, changing an already-published method signature, or reintroducing message-based failure classification.

Do not publish a known source-breaking patch merely because the project is pre-1.0.
