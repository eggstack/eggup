eggup-service — public API surface snapshot
============================================

Milestone: service-lifecycle 014 (M014), work package WP3.

already-closed service milestones 012 and 013 that are uncommitted in the

WHAT THIS FILE IS
-----------------
This is the *reviewable artifact* of the public-API surface guard. It lists
every public item of `eggup-service` with its kind and, where meaningful, its
signature, so that an intentional API change shows up as a diff here.

It is NOT the enforcement. The enforcement is the compile-only
signature-pinning test next to it, `tests/public_api_surface.rs`: a removed
item or a changed signature is a *compilation* error there, which fails
`cargo test --workspace --all-targets --all-features --locked` — the gate
`scripts/check-local.sh` already runs.

Regeneration (R-B8)
-------------------
The snapshot is maintained by hand. It is NOT auto-generated from the crate's
build output: the only tool that can emit a machine-readable public surface
from Rust sources is `cargo rustdoc -- -Z unstable-options --output-format
json`, which needs a nightly compiler and is therefore not part of the
stable/MSRV lanes this workspace gates on. No new dependency is added for it
(R-B8 / plan §14). The snapshot is instead verified two ways:

  1. by the enumeration command recorded below, and
  2. by the pinning test compiling — every entry below is bound to an
     explicit type there.

Enumeration command (R-B5)
--------------------------
    grep -n "^pub \(fn\|struct\|enum\|trait\|const\|static\|type\|mod\)" \
        crates/eggup-service/src/*.rs | wc -l

At the reviewed baseline this yields 68 top-level public items and 3 `pub use`
re-exports (plan §3.5). In the working tree that carries the already-closed
milestones 012 and 013, it yields 75 top-level public items and 5 `pub use`
re-exports. The guard covers *every* item that exists now; the counts differ
from the plan's baseline figures only because 012 and 013 landed in between.

Update process (R-B7)
---------------------
A change to this file, or to the pinning test, MUST be a deliberate,
separately-reviewed edit that states in the closure which public item changed
and why. A snapshot edit that is not accompanied by a stated API change is a
defect.
